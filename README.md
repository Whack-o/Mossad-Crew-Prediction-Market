# The Exchange — GitHub Pages prediction league

A lightweight multi-page static website for a small friend group. It uses plain HTML, CSS, and JavaScript; no build step, framework, Node.js server, or hosted application backend is required.

## Architecture

- **GitHub Pages:** hosts `index.html` and `create.html`.
- **`users.json`:** the simple username/password list and avatar paths.
- **Supabase `polls` table:** poll definitions, options, exclusions, deadlines, and resolutions.
- **Supabase `votes` table:** each person's current prediction.
- **`assets/avatars/`:** profile pictures committed to the repository.

The login is only a convenience gate. `users.json`, the website source, and the Supabase public key are visible to visitors. Anyone can inspect browser requests and potentially impersonate a username. Use this only as an informal joke game; do not reuse real passwords or store sensitive information.

## 1. Supabase setup

For a new database, run all of `supabase/schema.sql` in Supabase Dashboard → SQL Editor.

If you already set up the simplified two-table database, **do not rerun `schema.sql`** because that script resets the tables. Instead, run only `supabase/enable-poll-creation.sql`. This adds the permission needed for the create-poll page and preserves existing polls and votes.

The app uses the existing `polls` and `votes` tables. Poll fields are:

- `id` — unique text ID, generated by the create form.
- `question` — question text.
- `excluded` — JSON array of excluded usernames.
- `closing_date` — closing timestamp.
- `description` — optional text.
- `specifications` — optional additional specifications.
- `options` — JSON array of answer strings.
- `resolved` and `date_resolved` — initially NULL; managed in Supabase Table Editor when resolving.

The `votes` table stores `username`, `poll_id`, `choice`, and `updated_at`.

## 2. Configure the website

Edit `config.js` and set your Supabase Project URL and publishable (or legacy anon) key. The URL must be the base URL only, without `/rest/v1`.

Never place a Supabase secret or service-role key in the repository.

## 3. Configure players

Edit `users.json` with your players:

```json
[
  {
    "username": "peter",
    "password": "game-password-only",
    "avatar": "assets/avatars/peter.png"
  },
  {
    "username": "alex",
    "password": "another-game-password",
    "avatar": "assets/avatars/alex.png"
  }
]
```

Use unique lowercase usernames. Add the avatar image files under `assets/avatars/`. The login stores only the current username in browser local storage; it is not secure authentication.

## 4. Create polls from the website

After logging in, click **Create poll** in the main-page header. The form supports:

- Question and closing date/time (required).
- Description and additional specifications (optional).
- Two to twelve answer options.
- Excluded participants selected from the configured players.

The form inserts a new row into Supabase `polls`. The poll ID is generated automatically. New polls appear on the main page after returning or refreshing.

Any visitor can technically call the public insert endpoint because the site uses a client-side-only login and the public Supabase key. The form hides the create page from users without a locally stored username, but this is not a security boundary.

## 5. Resolve polls

Use Supabase → Table Editor → `polls`:

1. Set `resolved` to the exact correct option.
2. Set `date_resolved` to the resolution timestamp (including timezone).
3. Save both fields together.

Do not resolve a poll by editing its options. The database requires the resolved option to match an existing option.

## 6. Scoring

For each resolved poll:

- Correct prediction: one win.
- Incorrect prediction: one loss.
- No prediction: one loss.
- Excluded participant: neither win nor loss.

The leaderboard is calculated in the browser from `users.json`, `polls`, and `votes`.

## 7. Publish on GitHub Pages

1. Upload the **contents** of this project folder to the root of your GitHub repository.
2. Commit the files.
3. Open repository Settings → Pages.
4. Select **Deploy from a branch**, branch `main`, folder `/ (root)`, then save.
5. Open the published Pages URL.

To update an existing deployment, add `create.html` and `create-poll.js`, and replace `index.html` and `styles.css`. Keep your current `config.js`, `users.json`, and avatar files. Run `enable-poll-creation.sql` once in Supabase if you already have the two-table database.
